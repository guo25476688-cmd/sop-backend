# 02 · 企业级 RAG 知识体系设计

## 1. 核心原则：按「知识用途」而非「文档来源」划分

传统做法按来源建库（HR 文档库、市场部文档库…），检索时命中一堆同部门但不同用途的内容。
本平台按**这段知识在生成链路里扮演什么角色**来分四类：

| 知识库 | 里面放什么 | 谁来检索 | 检索目的 |
| --- | --- | --- | --- |
| **案例库** | 历史活动/项目的完整方案（含背景、结构、结果） | A1 大纲生成 | 找相似案例，参考它的阶段结构与踩坑点 |
| **流程规范库** | 公司制度、审批流、物料标准、预算口径 | A2 主表、A3 成果 | 做**合规约束**：生成的任务/成果不能违反规范 |
| **应用方案库** | 已沉淀、被验证过的可复用 SOP 模板 | A1、A2 | 命中同类型 → 直接复用模板，不从零生成 |
| **复盘优化库** | 历史复盘结论、归因、已落地的改进项 | R1、R2 | 提供归因视角与行动项参考 |

同一份文档可能被拆进多个库：一份"2025 高管工作坊复盘"，方案部分进案例库，结论部分进复盘优化库。

## 2. 分层切片策略

不同库的知识粒度不同，切片策略分层：

| 库 | 切片粒度 | 理由 |
| --- | --- | --- |
| 案例库 | **按阶段/章节切**（大块，500–800 字） | 大纲生成需要看到完整的"阶段是怎么组织的" |
| 流程规范库 | **按条款切**（小块，100–300 字） | 合规判断要精确定位到某一条，块太大会稀释 |
| 应用方案库 | **按模板段落切** + 保留模板结构元数据 | 复用时要能整段拼回去 |
| 复盘优化库 | **按"问题-归因-改进"三元组切** | 一个改进项就是一个可检索单元 |

每个切片额外挂父文档摘要（small-to-big），召回小块、喂给 LLM 时带上父级上下文。

## 3. Metadata 字段设计

所有切片统一打以下 Metadata，供检索时过滤：

| 字段 | 取值示例 | 用途 |
| --- | --- | --- |
| `kb_type` | `case` / `norm` / `template` / `retro` | 限定检索哪个库 |
| `activity_type` | 培训 / 发布会 / 内部工作坊 / 客户活动 | 按当前项目类型过滤 |
| `department` | 培训部 / 市场部 / … | 部门相关性 |
| `year` | 2024 / 2025 | 时效性，旧规范降权 |
| `doc_level` | 制度 / 参考 / 草稿 | 制度级不可被当作"参考"随意覆盖 |
| `confirmed` | true / false | 历史资料是否为已确认事实（见 §5） |

前端 A1 生成时把 `activity_type` / `department` 作为检索过滤条件下推，缩小召回范围。

## 4. 关键词 + 向量双路召回

### 为什么不能纯向量

企业知识里高频出现：

- 产品/课程型号：`AI-101`、`GX-2` —— 向量模型对这种"半随机字符串"几乎无语义
- 部门简称：`培运`、`市品` —— 训练语料里罕见
- 内部黑话：`老带新`、`三段式` —— 语义漂移严重

纯向量检索对这些**精确匹配需求**召回率明显偏低。

### 双路方案

```
query ──┬── 向量检索（语义相似，Top-K1）──┐
        │                                 ├── 合并去重 ── 重排 ── Top-N ──> LLM
        └── 关键词/BM25 检索（精确匹配，Top-K2）──┘
```

- 向量路负责"意思相近"
- 关键词路负责"必须出现这个词"，作为兜底
- 合并后按 `doc_level` / `year` 做轻量重排（制度级、近年优先）

## 5. 历史资料的"事实边界"

前端明确约束（见 `index.html` 知识来源面板）：

> 历史资料仅作**历史参考**，不可自动采用为当前项目的已确认事实。

实现上：召回的历史切片 `confirmed=false`，生成时 Prompt 强制要求——
引用历史数据必须标注来源与"待当前项目确认"，不得直接写成本项目结论。
这是"异常识别能力"评测维度的重点检查项。

## 6. 反馈回流

用户在前端对 AI 成果的修改（A4 助手 / 手动编辑 / 版本确认）会被捕获：

```
用户修改 diff ──> 归类（补充 / 纠错 / 联动调整）──> 人工审核 ──> 写入对应知识库
                                                            案例库 / 复盘优化库
```

形成 `测试 → 定位 → 优化 → 回归` 之外的第二条改进回路：真实使用数据反哺知识资产。

## 7. 现状

- 累计接入 **86 篇文档、约 15 万字**语料
- 覆盖案例库 / 流程规范库 / 应用方案库 / 复盘优化库四类
- 检索配置在 Dify 知识库侧维护，后端不直接触碰向量库
